# SmartDNS WebUI

Веб-панель для редактирования конфигурации [SmartDNS](https://github.com/pymumu/smartdns) на устройствах с Entware и веб-сервером `lighttpd`. Интерфейс рассчитан на роутеры и небольшие устройства, где предпочтительнее простая связка shell CGI + JavaScript без отдельного Node.js/PHP-сервера.

> **Важно:** в приложении нет встроенной авторизации. Не публикуйте порт панели в интернет и не перенаправляйте его на WAN. Используйте её только в доверенной локальной сети или через защищённый VPN. Доступ к панели даёт возможность менять DNS-конфигурацию и файлы списков.

## Возможности

- Визуальное редактирование основных параметров SmartDNS, DNS upstream-серверов и групп.
- Raw-режим для просмотра и редактирования исходного текста конфигурации.
- Управление файлами доменных списков `.list`.
- Редактирование директив маршрутизации `domain-set` / `nameserver`, а также поддерживаемых `ipset` / `nftset` записей.
- Просмотр и очистка доступного панели файла журнала SmartDNS.
- Проверка части логических ошибок перед сохранением.
- Режим тестирования UI, который направляет операции чтения/записи в отдельные тестовые пути и не выполняет реальный перезапуск SmartDNS.
- Отображение доступной версии и запуск обновления из интерфейса.

Визуальный редактор поддерживает только часть директив SmartDNS. Неизвестные и нестандартные директивы следует проверять в Raw-режиме. Перед сохранением важных изменений делайте резервную копию конфигурации.

## Как устроено приложение

- **Backend:** shell CGI (`index.cgi`, `api.sh`).
- **Frontend:** HTML, CSS и обычный JavaScript (`template.html`, `app.js`, `parser.js`).
- **Веб-сервер:** `lighttpd`.
- **Внешние ресурсы интерфейса:** Bootstrap, Bootstrap Icons, CodeMirror и SortableJS загружаются с CDN. Поэтому для полной стилизации, подсветки Raw-редактора и drag-and-drop нужен доступ браузера к соответствующим CDN. Это не полностью автономный/offline-интерфейс.
- **Отдельный Node.js/PHP/Python-сервер не требуется.**

## Требования

- Entware с рабочим `lighttpd`.
- Установленный и настроенный SmartDNS.
- `curl`, `sh` и стандартные утилиты Entware/BusyBox (`sed`, `cp`, `mv`, `chmod`, `mkdir`).
- Доступ по SSH с правами, достаточными для записи в `/opt/etc`, `/opt/share/www` и перезапуска `lighttpd`.
- Свободный TCP-порт **3000**.

Панель не устанавливает и не настраивает сам SmartDNS. Она предполагает, что SmartDNS уже установлен и использует конфигурационный файл `/opt/etc/smartdns/smartdns.conf`.

## Установка

Перед установкой убедитесь, что порт 3000 свободен и что конфигурация `lighttpd` не содержит конфликтующего блока для этого порта. Установщик использует следующие пути:

- Файлы приложения: `/opt/share/www/smartdns/`
- Конфигурация веб-сервера: `/opt/etc/lighttpd/conf.d/90-smartdns.conf`
- Конфигурация SmartDNS, с которой работает панель: `/opt/etc/smartdns/smartdns.conf`
- Журнал SmartDNS: `/opt/var/log/smartdns/smartdns.log`

### Способ 1: скачать, проверить и запустить

Подключитесь к роутеру по SSH. Скачайте установщик во временный файл, просмотрите его содержимое и только затем запускайте:

```sh
curl -fsSL https://raw.githubusercontent.com/KOPOHA-MACOHA/smartdns-webui/main/install.sh -o /opt/tmp/smartdns-webui-install.sh
less /opt/tmp/smartdns-webui-install.sh
sh /opt/tmp/smartdns-webui-install.sh
```

Если в системе нет `less`, откройте файл другой доступной утилитой, например `cat`.

После успешной установки откройте:

```
http://192.168.1.1:3000
```

Замените `192.168.1.1` на LAN-адрес своего роутера.

### Поведение установщика и статус улучшений

**В текущем `main` до принятия PR по безопасности** установщик скачивает файлы непосредственно в рабочий каталог, перезаписывает `90-smartdns.conf` и завершает процессы `lighttpd` через `killall -9`. В нём нет полноценного отката при неудачной загрузке или установке. Поэтому перед запуском текущего установщика обязательно вручную сохраните конфигурацию и файлы панели.

Отдельный Draft PR предлагает более безопасный порядок: скачать файлы во временный каталог, проверить HTTP-результат и shell-синтаксис, сохранить заменяемые файлы в резервную копию, установить их и выполнить штатный перезапуск с откатом при ошибке. Если этот PR ещё не принят, эти улучшения **не входят в опубликованный `main`**.

Даже в улучшенном варианте проверка shell-синтаксиса не подтверждает криптографическую подлинность скачанного кода. Файлы загружаются из ветки `main` по HTTPS; подписи релизов или закреплённые контрольные суммы пока не используются.

> Установщик из `main` скачивает опубликованные файлы `main`, а не код из открытого Draft PR или другой ветки.

## Использование

### Настройки

- **Визуальный режим** отображает поддерживаемые параметры и группы в форме.
- **Raw-режим** показывает текст конфигурации напрямую. Он нужен для директив, которые визуальный редактор не умеет полноценно представлять.
- **Сохранить** записывает изменения в конфигурационный файл. Сохранение и применение настроек - разные действия.
- **Рестарт** запрашивает перезапуск SmartDNS, чтобы применить сохранённую конфигурацию.

Не переключайтесь между Raw и визуальным режимом с несохранёнными изменениями без проверки результата. Парсер и генератор форматируют некоторые записи при переходе между режимами, поэтому для сложного или нестандартного конфига безопаснее редактировать Raw и хранить исходную копию.

### Списки

Во вкладке «Списки» можно создавать, редактировать и удалять файлы `.list` в:

```
/opt/etc/smartdns/domains/
```

Если конфигурация использует `domain-set -file`, путь и имя файла в конфиге должны совпадать с реально существующим файлом.

### Логи

Панель показывает файл:

```
/opt/var/log/smartdns/smartdns.log
```

Если SmartDNS пишет журнал в другое место или у пользователя веб-сервера нет прав на чтение, лог может быть пустым или недоступным.

### Тестовый режим

Переключатель «Тест-режим» предназначен для проверки интерфейса без записи в основные файлы конфигурации. В этом режиме API использует тестовые пути под `/opt/tmp`, а перезапуск сервиса имитируется. Это **не** полноценная песочница: проверяйте код и запросы перед использованием и не считайте тестовый режим заменой резервной копии.

### Обновление

Кнопка версии проверяет `version.txt` в ветке `main` и при обнаружении другой версии предлагает запустить установщик. **В текущем `main` механизм обновления запускает скачанный установщик через shell pipe без предварительной проверки файла и не предоставляет надёжного подтверждения завершения операции.** Это известное ограничение; улучшение механизма обновления находится в Draft PR и ещё не выпущено.

В предложенной версии обновления результат фонового процесса записывается в:

```
/opt/var/log/smartdns-webui-update.log
```

Перед обновлением сохраните резервную копию и проверьте, что в `90-smartdns.conf` нет собственных изменений. Даже после улучшения загрузка будет идти из `main` без подписей и закреплённого хеша.

## Резервное копирование и восстановление

Перед ручным редактированием или обновлением рекомендуется сохранить как минимум:

- `/opt/etc/smartdns/smartdns.conf`
- `/opt/etc/smartdns/domains/`
- `/opt/etc/lighttpd/conf.d/90-smartdns.conf`
- `/opt/share/www/smartdns/`

Установщик создаёт резервные копии заменяемых файлов приложения и своего конфига lighttpd в каталоге `/opt/var/backups/smartdns-webui/`. Эти копии не заменяют отдельную резервную копию конфигурации SmartDNS и доменных списков.

## Удаление

Удаление панели не должно удалять SmartDNS или его конфигурацию. Чтобы отключить панель:

1. Сохраните копию `/opt/etc/lighttpd/conf.d/90-smartdns.conf`.
2. Удалите или переместите этот файл, чтобы lighttpd больше не создавал endpoint панели на порту 3000.
3. Проверьте конфигурацию lighttpd и перезапустите его штатным init-скриптом.
4. После проверки можно удалить каталог приложения `/opt/share/www/smartdns/`.
5. При необходимости отдельно удалите резервные копии `/opt/var/backups/smartdns-webui/`.

Не удаляйте каталоги SmartDNS и `/opt/etc/smartdns/domains/`, если продолжаете пользоваться самим SmartDNS.

## Диагностика

- **Панель не открывается:** проверьте, запущен ли `lighttpd`, свободен ли порт 3000 и загружен ли `90-smartdns.conf`.
- **Пустая вкладка логов:** проверьте, существует ли `/opt/var/log/smartdns/smartdns.log` и пишет ли туда SmartDNS.
- **Не работают стили или редактор:** проверьте доступ браузера к CDN Bootstrap, Bootstrap Icons, CodeMirror и SortableJS.
- **Сохранение/обновление не удалось:** проверьте права записи, свободное место в `/opt`, доступ к GitHub и журнал обновления.
- **После изменения конфига SmartDNS не стартует:** верните последнюю рабочую копию `/opt/etc/smartdns/smartdns.conf`, затем проверьте синтаксис средствами установленной версии SmartDNS.

## Разработка и статус

Изменения проекта следует делать в отдельных ветках и проверять через Pull Request. Не тестируйте экспериментальные установщики на рабочем роутере без предварительной резервной копии и понятного плана отката.

Проект рассчитан на Entware + `lighttpd` + установленный SmartDNS. Совместимость с конкретными моделями роутеров и версиями пакетов зависит от их конфигурации; изменения установщика и API нужно проверять на целевом устройстве перед выпуском.

### Запланированные улучшения безопасности

- **Авторизация через root Entware (планируется):** закрыть веб-панель и все CGI/API-маршруты HTTP Basic Auth на уровне `lighttpd`. Не передавать пароль root в JavaScript, CGI или API-запросах; секрет хранить отдельно с ограниченными правами. Предусмотреть безопасную первичную настройку/смену пароля и закрытый доступ по умолчанию, если аутентификация не настроена.
- Проверить совместимость механизма авторизации с используемой сборкой `lighttpd` и доступными в Entware средствами проверки пароля. Не предполагать, что пароль из системного `/etc/shadow` можно напрямую использовать как файл Basic Auth.
- Проверить защиту прямого доступа к `api.sh`, тестового режима и всех маршрутов, а также сценарии неверного пароля и отсутствующего файла учётных данных.

Эта функция пока **не реализована**. До её выпуска панель следует использовать только в доверенной LAN или через VPN; не открывать порт 3000 в WAN.
