# Ближайший план SmartDNS WebUI

Обновлён 29.10.2026. Версия 1.8.9 с именами клиентов выпущена. Специального блока Fallback в Core больше нет; импортированная группа с таким именем редактируется как обычная DNS-группа. Это не изменяет семантику сервера и не добавляет директив резервирования.

## 1. Вход внутри сайта

- Страница входа в теме интерфейса, состояние сессии и кнопка выхода вместо HTTP Basic и браузерного диалога.
- Сохранить проверку существующего пароля Entware; не копировать пароль в настройки WebUI.
- Непредсказуемые сессии с ограниченным сроком, защищёнными файлами и cookie HttpOnly/SameSite; Secure при HTTPS. Выход и истечение срока отзывают доступ.
- Защищать все API и конфигурационные данные, проверять Origin/CSRF для изменений, ограничивать подбор пароля. Просроченная сессия не должна терять черновик в открытой вкладке.
- Тесты: обход входа, фиксация/подделка/истечение/отзыв сессии, CSRF, неверный пароль, недоступность файла учётных данных. Перезапуск DNS не требуется.

## 2. Нормальная поставка и обновление

- Подготовить IPK для текущего CGI/JS-интерфейса: код не зависит от CPU, допустима архитектура all с проверенными зависимостями и поддерживаемой средой.
- Установка/обновление/удаление должны сохранять пользовательские DNS-конфиги и списки; проверка артефактов, резервная копия и откат версии UI.
- Перенести статические зависимости с CDN в пакет с учётом лицензий и размера, проверить работу без доступа к внешним сайтам.

## 3. Прототип собственного сервера

- Отдельно сравнить нынешний CGI с небольшим сервером Go и встроенными статическими файлами; бинарник не является обязательным условием развития проекта.
- Сборки-кандидаты: linux/mipsle softfloat, linux/mips softfloat, linux/arm64; amd64 для разработки. Поддержка каждой модели зависит также от ABI, ядра, окружения Entware и привилегий, а не только от названия CPU.
- Измерить RSS/CPU в простое, при входе, чтении журнала, работе нескольких вкладок и проверке конфигурации. Не заменять текущую реализацию только ради единого бинарника.
- Сохранить отдельный независимый watchdog применения: отказ веб-сервера не должен выключать откат DNS.
- Приёмка сначала на устройстве с ограниченной RAM. Тестовая сборка для других архитектур сама по себе не доказывает совместимость.

## 4. Возможности DNS и списков

- Проксирующие DNS-группы и правила, требующие именно такие ответы; согласованный набор допустимых резервов для каждого правила.
- Geohide: выбор сервисов, проверка изменений списка по запросу, сохранение ручных дополнений и diff перед принятием.
- Обновление адресов провайдеров: недоступный или изменившийся сайт не должен менять рабочую конфигурацию.
- История конфигураций и восстановление, поиск и пересечения между файлами, проверка ссылок перед удалением списков.

## 5. Доработка надёжности и приёмка

- Восстановление подтверждённого статуса применения после обновления страницы; оценка ускорения проверок без ослабления отката.
- Приёмка на настоящем телефоне с экранной клавиатурой; остающиеся замечания по интерфейсу и журналу.
- SmartDNS 48.4 остаётся отдельным исследованием. Автоматически устанавливать его ради резерва не планируется; проверять фактическое поведение при таймауте, SERVFAIL и ограничениях маршрутизационных групп.

Источники для архитектур Go: https://go.dev/doc/install/source#environment
