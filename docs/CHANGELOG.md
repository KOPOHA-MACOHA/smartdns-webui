# Изменения

## 1.7.0 — 2026-10-23 (предпросмотр)

- Первый этап оформления в стиле Keenetic: плоские секции, бирюзовые акценты,
  единая шапка, типографика и подчёркнутые переключатели UI/Raw.
- Основные параметры, DNS-группы и маршрутизация перенесены в боковое меню.
  Меню сворачивается до иконок; выбор запоминается в браузере.
- На телефоне используется выдвижное меню с закрытием по Escape, возвратом
  фокуса и блокировкой фонового содержимого.
- CSS вынесен в ui.css вместо накопленных адаптивных переопределений в шаблоне.
- Навигация и сворачивание не изменяют черновики; undo сохраняет выбранный раздел.
- 72 JS-теста проходят. Предпросмотр проверен в браузере на 360/390 и 1440 px,
  в обеих темах. Проверка установки на роутер — отдельный этап приёмки.

## 1.6.1 — 2026-10-23

- Ctrl+Z / Ctrl+Y / Ctrl+Shift+Z распознаются по физическим клавишам и работают
  в русской раскладке. Ctrl+S исправлен аналогично.
- Отмена работает после выбора списка или переключателя, даже если фокус
  оказался на странице после перерисовки. В отдельных полях вне редактора
  и диалогах стандартная отмена сохраняется.
- 69 JS-тестов проходят, включая смену группы маршрута, переключатели,
  флажки, выпадающие списки и повтор после отмены с русской раскладкой.

## 1.6.0 — 2026-10-23

- Единая панель «Изменения» для конфигурации и списков: выбор файла, статус,
  отмена/повтор, diff, сброс, перечитывание, сохранение и применение.
- Одна история вместо отдельных механизмов визуального редактора и CodeMirror.
  Черновики и история сохраняются при смене разделов и UI/Raw в сеансе страницы.
- Создание/удаление списков сначала меняет черновик; запись только через «Сохранить».
- Поздние правки не теряются при завершении сохранения ранее одобренного снимка.
- Статус применения подтверждается только событием COMMITTED. Открытие файла
  не объявляет работающий DNS проверенным.
- История ограничена 40 действиями на файл и работает в браузере. Перезагрузка
  страницы теряет черновики; при несохранённых файлах браузер запрашивает выход.
- 67 JS-тестов проходят; обновление WebUI не требует перезапуска DNS.

## 1.5.3 — 2026-10-23

- После статуса `COMMITTED` окно применения закрывается автоматически и
  возвращает фокус прежнему элементу. Подтверждение работы сети остаётся ручным.
- Отклонение, откат и ошибки остаются видимыми до ручного закрытия.
- 57 JS-тестов прошли. Изменение интерфейса не требует перезапуска DNS.

## 1.5.2 — 2026-10-23

- Добавлен возврат из расширенных адресов к единому порту UDP/TCP без потери
  настроек; для несовместимых bind показывается причина отказа. Выбор режима
  запоминается в браузере, но сложные конфиги всегда остаются расширенными.
- Действие «Разложить DNS по блокам» перенесено в инструменты Raw над текстом.
- 55 JS-тестов прошли. Обновление затрагивает только WebUI, без рестарта DNS.

## 1.5.1 — 2026-10-23

- Для совпадающей пары UDP/TCP bind добавлено единое числовое поле порта
  с диапазоном 1–65535. Адрес IPv4/IPv6 сохраняется автоматически.
  Различающиеся адреса, дополнительные bind и аргументы открываются в
  расширенном режиме. Открытие расширенного режима не меняет конфигурацию.
- 52 JS-теста прошли, включая сохранение адресов, проверку порта и сложные bind.

## 1.5.0 — 2026-10-23 (локальная сборка)

- Визуальные поля для нескольких `bind-tcp`, `force-AAAA-SOA` и `cache-persist`.
  Отсутствующие параметры не добавляются при обычном сохранении. Дополнительные
  параметры Core доступны в текстовом поле вместо скрытого input.
- Пояснения «?» у параметров, DNS-разделов, групп, маршрутов и ручных адресов.
  Открываются нажатием или с клавиатуры, используют цвета общей темы;
  работают в браузере без фоновых запросов к роутеру.
- Кнопка «Разложить DNS по блокам» переносит строки серверов по их аргументам
  под известные заголовки Raw. Сохраняются аргументы, отключённые серверы,
  комментарии и переводы строк. Комментарии остаются на исходных местах.
  Действие меняет только редактор; перед сохранением показывается обычный diff.
  Обычное сохранение по-прежнему не перестраивает файл.
- 50 JS-тестов прошли, в том числе новые проверки полей, подсказок и раскладки.
  На роутер эта версия пока не установлена; рабочий DNS не изменялся.

## 1.4.1 — 2026-10-23

- Безопасное применение поддерживает обычные IPv6 bind `[::]:53` / `[::1]:53`.
  После рестарта дополнительно проверяются UDP/TCP через `::1`; проверки IPv4
  сохраняются. Добавлены проверки плана и выбора адреса/транспорта probe.

## 1.4.0 — 2026-10-23

- Добавлена отдельная транзакция применения: снимки, независимый сторож,
  нативный тест прежнего файла и кандидата, проверка DNS и ручное подтверждение.
- Ошибки и отсутствие подтверждения вызывают восстановление прежнего файла;
  неуспешное восстановление явно фиксируется и удерживает блокировки.
- Окно статуса поддерживает общую тему, повторное открытие и потерю соединения.
  Старый прямой рестарт рабочего DNS через API отключён.
- Функция по умолчанию закрыта серверным переключателем; установщик её
  автоматически не включает. Испытания на фиктивной службе не заменяют приёмку
  настоящего рестарта. Ограничения и порядок: [SAFE-APPLY.md](SAFE-APPLY.md).

## 1.3.0 — 2026-10-22

- Добавлена ручная кнопка «Тест DNS»: отдельный ограниченный экземпляр SmartDNS
  проверяет снимок редактора, без записи рабочего конфига или рестарта службы.
- Проверяются отдельный PID, UDP/TCP контрольного экземпляра, используемые группы
  и маршруты. Списки копируются, записываемые файлы и порты изолированы.
- Введены лимиты времени/ресурсов и общая блокировка теста и перезапуска.
  Нет фонового опроса; проверка не выполняется на каждый запрос или сохранение.
- Не поддержанные безопасной подготовкой конструкции не исполняются и не
  удаляются из рабочего конфига. Границы описаны в PREFLIGHT.md.
- Роадмап уточнён: Keenetic — образец для всей панели, а не только меню/карточек.

Применение с автоматическим откатом ещё не встроено. Это отдельный следующий
этап с проверкой реального перезапуска только по явному разрешению пользователя.

## 1.2.0 — 2026-10-22

Проверенная локальная сборка для роутера. Публикация релиза GitHub и слияние
ветки в main выполняются отдельно.

- Добавлен серверный валидатор с профилем SmartDNS 46.1 и кнопка «Проверить»
  без записи/перезапуска. Отчёт различает ошибки, предупреждения и выключенные
  неподдерживаемые строки; поддерживает общую тему панели.
- Перед сохранением повторяется серверная проверка, которую нельзя обойти
  отключением JavaScript. Проверяются аргументы upstream, используемые группы,
  domain-set и доступность файлов списков. Подробные границы — в VALIDATION.md.
- Нативная проба Entware 46.1 подтвердила: H3/QUIC не создают upstream, но при
  наличии обычного UDP upstream процесс продолжает работать. Поэтому активная
  строка даёт предупреждение; отсутствие поддерживаемых серверов используемой
  группы блокирует запись. Текст конфига автоматически не исправляется.

- Сохранение проверяет версию файла до просмотра diff и повторно под серверной
  блокировкой перед записью. Устаревший сеанс получает конфликт, правки остаются
  в редакторе. Старые вкладки без версии файла должны обновить страницу.
- Перед атомарной заменой создаётся отдельная резервная копия, максимум 20 файлов. Ошибка создания
  копии останавливает запись. Права исходного конфига сохраняются.

- Визуальный редактор применяет изменения к исходному тексту вместо пересборки
  всего файла: сохраняются расположение строк, пользовательские заголовки,
  комментарии, пустые строки и окончания строк. Без правок файл возвращается
  побайтно без изменений. Проверен сценарий включения одного upstream из
  восстановленного конфига и сохранение метаданных при размещении карточек.

- Добавлен просмотр изменённого блока конфигурации перед сохранением с чтением
  текущего файла на роутере. Отмена и ошибка чтения останавливают запись;
  содержимое отображается как текст, без выполнения HTML.
- Визуальные DNS-поля снова показывают адреса; исходные параметры серверов
  сохраняются отдельно. Добавлены проверки изменения адреса, удаления,
  перестановки и выключения записи.
- Оформление в стиле Keenetic запланировано в P3: боковое меню, единый вид
  карточек и адаптация для узких экранов.

Защита от параллельной записи после просмотра включена в эту сборку.
DNS-проверки и автоматический откат остаются следующими шагами P2.

## 1.1.3

- Сохранение не удаляет запятые между IP в ручных `address`.
- Существующие серверные строки сохраняют принадлежность основной и
  именованным группам, повторные `-group`, исключения и bootstrap-параметры.
- Переименование карточки группы сохраняет дополнительные группы сервера.
- Полный `bind` с IPv4/IPv6 и параметрами больше не получает лишнее двоеточие;
  дополнительные строки `bind` сохраняются.
- Отсутствующий `speed-check-mode` не добавляется автоматически; исходный
  порядок и дополнительные проверки сохраняются при обычном сохранении.
- Меню `response-mode` предлагает `fastest-response`, `first-ping`, `fastest-ip`.
  Импортированное неизвестное значение остаётся видимым и проверяется перед
  сохранением вместо молчаливой замены.
- Валидатор сообщает о нескольких URL upstream в одной директиве и
  неподдерживаемом значении `response-mode`.
- Карточка `fallback` поясняет, что это обычная именованная группа.
- Добавлены DOM-регрессионные тесты и установка тестовых зависимостей в CI.

Статическая проверка не заменяет проверку установленным SmartDNS. Полная
поддержка всех вариантов его синтаксиса и автоматический откат при применении
через WebUI остаются отдельными задачами.
