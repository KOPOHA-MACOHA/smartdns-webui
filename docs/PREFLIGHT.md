# Ручная проверка кандидата отдельным SmartDNS

Кнопка «Тест DNS» проверяет снимок текущего редактора. Она не сохраняет файл,
не вызывает init.d, не меняет LAN DNS и не перезапускает рабочий SmartDNS.
Обычное сохранение остаётся со статической проверкой. Автоприменение и откат
в эту функцию не входят; успешный тест не гарантирует будущее состояние сети.

## Что проверяется

1. Серверная статическая проверка 46.1 и допустимость безопасной подготовки.
2. Снимки обычных списков и копия с localhost-слушателями 16530–16538.
3. Конкретный дочерний PID: бинарник, родитель и время старта, а не pidof/killall.
4. Ответ контрольной записи только пробного экземпляра по UDP и TCP.
5. Контрольный A-ответ example.org для default, ответы используемых групп и
   маршрутов по первому подходящему домену списка. Для произвольных доменов
   допустимы NOERROR/NXDOMAIN, включая отсутствие A; SERVFAIL/REFUSED/таймаут
   не принимаются. Ожидаемый IP каждого реального домена не устанавливается.
6. Остановка только этого экземпляра и освобождение портов/блокировки.

На пробных слушателях отключён кэш ответов, чтобы предыдущая проба не подменяла
результат следующей. Заданы отдельные PID/cache/log/audit/debug-пути, кэш 64
записи, prefetch/serve-expired/cache-persist выключены. Исходный текст с его
параметрами не меняется. Рабочие параметры кэша и исходные bind/cert-пути не
считаются проверенными этим запуском. Подготовка использует лексер валидатора.

## Ресурсы и завершение

- Только вручную, один тест/операция службы за раз; перезапуск из другой вкладки
  отклоняется общей блокировкой `/tmp/smartdns-webui-dns-operation.lock`.
- Начало только при MemAvailable >= 32 МБ, приоритет nice +10.
- Нативному ребёнку: виртуальная память <= 96 МБ, CPU <= 8 с, FD <= 256,
  core dump запрещён, timeout 30 с + 2 с на принудительное завершение.
- RSS проверяется раз в секунду: при >16 МБ либо MemAvailable <8 МБ ребёнок
  останавливается. Это наблюдаемый порог, не жёсткий лимит физической RAM.
- Запросы ограничены 25 с; весь серверный вызов — 45 с + 3 с на завершение.
- Кандидат <=256 КБ, до 16 списков по 1 МБ, до 8 используемых групп и 8 маршрутов.
- TERM/HUP/INT очищают процессы/файлы/порты. Дополнительный timeout ограничивает
  жизнь ребёнка при потере управляющего процесса. После SIGKILL может остаться
  блокировка: её owner нужен для диагностики; она не удаляется автоматически
  по одному PID, чтобы не допустить гонку. Перезагрузка очищает `/tmp`.

## Консервативные ограничения

Поддержан профиль 46.1 и простой плоский конфиг. Плагины, conf-file, контексты,
ipset/nftset/domain-rules, произвольные файлы hosts, прокси и неизвестные
конструкции не исполняются. Программа возвращает «проверка недоступна», а не
объявляет такой исходный конфиг заведомо сломанным. В исходнике они сохраняются.
Нужен явный IP-upstream/host-ip; автоматическая подстановка системного DNS
вместо отсутствующего upstream не используется. Полная сетевая namespace-
изоляция не создаётся: обращения идут к настроенным upstream обычными маршрутами.
Bootstrap, TLS и сеть могут дать временный сбой; проверка не отключает TLS-проверку.

## Проверено на Keenetic

Тестовый локальный upstream: успешные UDP/TCP, группа/маршрут, отказ upstream,
прерывание, отсутствие оставшихся слушателей, блокировка рестарта. Рабочий файл
и PID сохранились. Копия реального конфига: 4 группы, 5 маршрутов, ~6,9 с,
пиковый RSS ребёнка 9260 КБ; суммарное CPU-время измеренного запуска ~4,26 с.
Это разовая проверка, не фоновый демон и не стресс-тест всех служб.

Подготовка: `sh tests/preflight-prepare.test.sh`; нативные интеграционные тесты:
`sh tests/preflight-router.test.sh` (только Entware, иначе SKIP).
