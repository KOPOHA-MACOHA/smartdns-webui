# Проверка конфигурации

Кнопка «Проверить» проверяет текст редактора на роутере без сохранения и
перезапуска SmartDNS. При сохранении проверяется тот же текст; сервер повторяет
проверку под блокировкой перед заменой файла. Изменение HTTP-запроса не обходит
блокирующие правила. Резервная копия создаётся только после успешной проверки.

## Уровни

- Ошибка: сохранение запрещено; в отчёте указана исходная строка.
- Предупреждение: требуется подтверждение перед просмотром diff.
- Информация: выключенная строка не влияет на работу; показывается свёрнуто.

## Профиль 46.1

Список из 101 директивы и их типы взят из
[таблицы исходников Release46.1](https://github.com/pymumu/smartdns/blob/Release46.1/src/dns_conf.c).
Файл `validator-46.1.txt` поставляется локально: доступ к документации по сети
во время проверки не требуется. Версия определяется установленным бинарником.
Для другой версии показывается предупреждение о неполной совместимости;
профиль 46.1 не выдаётся за профиль новой сборки.

Проверяются неизвестные директивы 46.1, значения yes/no, основные числовые
параметры и перечисления, кавычки, адреса/порты upstream, аргументы upstream,
обязательные значения, ссылки на группы и domain-set, доступность обычных файлов
domain-set. Поддерживаются короткие `-g`, `-e`, повторные группы, параметры с `=`,
кавычки и относительные пути списков.

На установленном Entware 46.1 отдельно проверены `server-h3` и `server-quic`:
с обычным UDP upstream процесс продолжает работу, сообщая `unsupported config`.
Поэтому такие активные строки дают предупреждение, но не считаются upstream.
Если используемая группа остаётся без поддерживаемых серверов, это ошибка.
Выключенные H3/QUIC-строки дают только информацию; их текст не меняется.

## Границы

Это статическая проверка, а не запуск полного конфига и не проверка сети.
Она не гарантирует доступность upstream, корректность сертификатов, отсутствие
блокировки соединения или успешный старт службы на рабочем порту.
Расширенные контексты (`group-begin`, `client-rules` и т. п.) и подключаемые
`conf-file` не раскрываются: вместо ложного вывода о группах показывается
предупреждение об ограничении. Содержимое списков и полная грамматика всех 101
директивы пока не проверяются. Шаблоны путей списков требуют отдельной проверки.

Проверка не выполняет команды из конфига, не загружает плагины, не запускает
дополнительную DNS-службу и не делает сетевых запросов. Это важно для RAM
Keenetic. Проверка DNS после применения и автоматический откат — следующий этап.

В 1.3.0 добавлена отдельная ручная кнопка «Тест DNS» для проверки кандидата
пробным экземпляром. Её режим и ограничения описаны в [PREFLIGHT.md](PREFLIGHT.md).
Она не заменяет проверку после реального применения.

В 46.1 отсутствие всех `bind` не означает синтаксическую ошибку: исходники
добавляют UDP `[::]:53`. Поэтому выдаётся предупреждение; при этом проверяется
наличие поддерживаемых upstream для используемой по умолчанию группы.

## Измерение нагрузки

2026-10-22, Keenetic Hopper, три последовательные проверки рабочего конфига:
0,39–0,52 с времени выполнения, 0,36–0,40 с суммарного CPU-времени на проверку,
пиковый RSS по BusyBox time 2720–2740 КБ. Это не суммарный расход памяти всех
процессов роутера и не стресс-тест одновременной работы всех сетевых служб.
На короткое время проверка занимала 77–93% одного CPU. Постоянного процесса
валидатора нет. Просмотр diff и построение карточек выполняются в браузере.

## Тесты

`npm test` проверяет обработку отчётов и интерфейс. `sh tests/validator.test.sh`
проверяет серверные правила и запрет прямого сохранения ошибочного конфига на
одноразовых файлах. Этот сценарий также выполнен на BusyBox Keenetic.
