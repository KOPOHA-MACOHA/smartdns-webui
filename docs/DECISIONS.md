# Журнал решений проекта

## 2026-10-29 — согласование дальнейшего развития

Обсуждение завершилось фиксацией плана; реализацию перечисленных ниже функций в этой задаче не начинали.

1. Сделать вход внутри сайта с сохранением авторизации после закрытия браузера и перезапуска роутера. Сначала изучить сессии nfqws2. Кнопка «Выйти» в шапке не нужна; конкретный срок сессии пока не выбран.
2. Выпускать готовый IPK существующего CGI/JS WebUI. Разные бинарники, Go и переписывание сервера сейчас не нужны.
3. Далее: понятное применение и восстановление конфигураций, документация проксирующих DNS и источники списков, затем резервирование проксирующих групп.
4. В документации нужны только активные серверы, официальные ссылки провайдеров и безопасные команды добавления. Персональные ссылки и токены нельзя публиковать как общие примеры.
5. Начать источники с Geohide и импорта по URL, с ручной проверкой изменений. При отказе источника сохранять рабочие списки; не добавлять постоянный опрос по умолчанию.
6. Резервные группы выбираются отдельно для каждого правила; успешного DNS-ответа недостаточно для проверки проксирования. Автоматизацию вводить после ручного режима и определения критериев отказа.
7. Проверка на «реальном телефоне» означает физическое устройство с экранной клавиатурой и сенсорным управлением.
8. Оставаться на SmartDNS из официального Entware. Его новая версия, сборка и форк — отдельная история, не задача развития WebUI.
9. Дополнительные идеи: полезнее структурировать журнал, показывать зависимости перед удалением, искать между списками, убирать редкие действия с основных экранов.
10. Готовые изменения сливать после проверок в main и убирать завершённые ветки. В этой задаче меняется только документация; версия приложения не повышается.

Полный актуальный порядок и критерии: [NEXT-STEPS.md](NEXT-STEPS.md). Если старый роадмап расходится с этим решением, для новых работ руководствоваться данным планом.
