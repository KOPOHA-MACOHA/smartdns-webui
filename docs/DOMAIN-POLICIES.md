# Правила обработки доменов

В WebUI 1.9.0 блок находится в разделе «Правила и статика». Одна карточка задаёт отдельные настройки DNS для домена, его поддоменов или существующего domain-set. Несколько доменов можно вводить по одному на строку.

В отличие от локальной записи address, правило не задаёт постоянный IP: адрес ищется через выбранные DNS-серверы. DNS-группа сама по себе не направляет пользовательский трафик в VPN.

- DNS-группа: отдельный набор upstream или наследование существующих правил.
- Выбор IP: быстрый DNS-ответ, первый доступный IP или IP с наименьшей задержкой.
- Проверка доступности: TCP 443, TCP 80, Ping, TCP 443 затем Ping или отключение проверки. Импортированный иной метод сохраняется. Проверка TCP не измеряет скорость загрузки и не подтверждает работу сервиса.
- Просроченный кэш: наследовать общие настройки либо запретить ответы с истёкшим TTL. Действующий кэш не отключается.
- DNS-записи HTTPS: оставить существующее поведение либо возвращать пустой ответ для типа 65. HTTPS-сайты не блокируются; QUIC/HTTP3 этим не запрещается.

Пример для вымышленного домена:

```text
domain-rules /images.example/ -nameserver images -response-mode fastest-ip -speed-check-mode tcp:443 -no-serve-expired
https-record /images.example/#
```

Группа images должна существовать и содержать активные upstream. Для набора используется селектор /domain-set:имя/; сам набор должен быть объявлен.

Неизвестные дополнительные аргументы сохраняются; для их редактирования используется Raw. Сложные формы, пользовательские HTTPS-записи и конфиги с group-begin/group-end не преобразуются автоматически в карточки. Повторяющиеся правила не объединяются при открытии. Неизменённые строки сохраняются в исходном виде, включая комментарии и отступы.

Настройки поддерживаются SmartDNS 46.1. Изолированная проверка принимает только разрешённые аргументы domain-rules: -nameserver, -response-mode, -speed-check-mode и -no-serve-expired. Побочные действия, включая ipset/nftset и смену области group, остаются запрещены в тестовом процессе. Ограничения числа проверяемых групп и списков сохраняются.

Обновление WebUI не применяет конфиг и не перезапускает DNS. Новые правила проходят обычный просмотр изменений и защищённое применение. Форма выполняется в браузере, дополнительных демонов и фонового опроса нет.

## Обработка DNS в карточках маршрутизации (1.9.3)

В каждой карточке маршрутизации доступен раскрывающийся раздел «Обработка DNS»: выбор IP, проверка доступности, просроченный кэш и HTTPS-записи. Пустые значения наследуют общие настройки. Правило применяется ко всем файлам domain-set; DNS-группа выбирается в основном поле карточки.

Поддерживаемые активные domain-rules и блокировки HTTPS для существующего набора показываются внутри карточки, без отдельной копии. Неизменённые строки сохраняются точно; при переименовании набора обновляются ссылки, при удалении карточки удаляются и прикреплённые правила. Отключённые, сложные правила или правила с отдельной конфликтующей DNS-группой остаются в отдельном блоке/Raw. Сброс всех переопределений удаляет только настройки обработки, сохраняя набор и выбор DNS-группы.
